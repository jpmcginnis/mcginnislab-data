1. Cohort inclusion criteria

Inclusion

  • Human (Homo sapiens), postmortem or surgical
  • snATAC-seq or 10x Multiome (snRNA + snATAC same-nucleus)
  • Public, redistributable deposit (no dbGaP / Synapse DUA data)
  • Any brain region (cerebellum, cortex, basal ganglia, brainstem, hippocampus, substantia nigra)
  • Fetal through aged donors

Exclusion

  • Alzheimer's disease (AD) or AD-related dementias (ADRD) donors
  • Parkinson's disease donors (except non-disease regions from PD cohorts, e.g. cortex from PD studies)
  • Clinically demented (MMSE ≤ 24, CDR ≥ 1)
  • Any donor with ADNC intermediate/high (A2–3, B2–3, C2–3)
  • Diffuse Lewy body disease (DLBD), FTLD-Tau, PSP, corticobasal degeneration
  • Non-brain tissue (except GSE300782 spinal cord retained as sidecar)
Borderline controls: clinically NCI donors with incidental age-related pathology at autopsy are dropped if ADNC ≥ low (A1 with B2+ or C2+), DLB of any stage, or clinically significant subdural hematoma. Retained if ADNC = 0 and Braak ≤ II.

3. Reference backbone peak set

CATLAS v2 2024 (Li et al., Science) — 1,012,572 cCRE regions assembled from 2.3M nuclei across 42 human brain regions.

  • Fetched from original source and cached at s3://jpm-atacseq-archive-2026/catlas/catlas_full_annotated.h5ad
  • Variable widths (median 598 bp; max 36 kb; min 1 bp)
  • Standard chromosomes only (chr1–chr22, chrX, chrY, chrM); 12,880 non-standard contig rows filtered out

4. Per-cohort peak extraction

Each cohort's author-called peak BED was recovered from its GEO deposit via the appropriate parser:

  • 10x matrix format (features.tsv.gz with Peaks feature type): parsed and emitted as BED
  • cellranger-arc .h5 output: peaks read from /matrix/features group
  • Author-released .peaks.bed: used directly
  • RDS / SummarizedExperiment: converted via custom R utility (rds_to_mtx.R)

For each cohort, peaks were filtered to intervals with end > start and dropped if on non-standard contigs.

5. Intermediate reference union (v2.1 backbone)

Built from CATLAS v2 2024 plus 9 cohorts whose ingested h5ad var preserved full peak coordinates:

geo-GSE266303, geo-GSE296139, geo-GSE296329, geo-GSE246443, geo-GSE256207, geo-GSE147672, hwang-girgenti-ptsd, zen-19-aerts-pd-cc, zen-19-aerts-pd-sn

Construction:

  1. Concatenate CATLAS + 9 cohort peak BEDs
  2. Sort by chromosome then start
  3. bedtools merge with default parameters (merges overlapping or touching intervals)

Result: 1,965,262 non-overlapping peaks in narrow_union_v2.1.bed.

6. v2.2 true union construction

Problem addressed: 20 of 30 cohorts had been collapsed onto a reference axis during initial ingest, losing their native author peak boundaries. Group-2 author peaks were recovered from S3 Deep Archive (Standard-tier restore, ~5 hr wait).

Backbone: v2.1 union (1,965,262 peaks).

Group-2 cohorts (17, whose author peaks were restored):

4dn-hippocampus · cxg-1-wang-kriegstein (fetal) · cxg-2-veiga-adolescent · cxg-3-braun-linnarsson · geo-GSE174367 · geo-GSE178451 · geo-GSE193688 · geo-GSE207334 · geo-GSE212630 · geo-GSE214979 · geo-GSE259298 · geo-GSE288939 · geo-GSE296943 · geo-GSE305146 · geo-GSE325789 · geo-GSE336954 · sea-ad

Algorithm

  1. For each Group-2 cohort, filter raw peak BED to standard chromosomes and valid intervals; sort by chrom, start
  2. Retain only peaks not overlapping the backbone by ≥50% reciprocal fraction (bedtools intersect -v -f 0.5) — the cohort's "novel" contribution
  3. Preserve each novel peak as-is (cohort-native boundaries); tag with source cohort
  4. Combine backbone + raw novel peaks per cohort → sort → final union (no cross-cohort merge, to avoid density-driven chain-merging into mega-peaks)

Replicability threshold: ≥1 study (loose)

The alternative ≥2-study filter (GBM-atlas convention) yielded only 27,832 novel peaks total and would have dropped unique single-cohort biology:

  • Wang-Kriegstein fetal cortex: 68,946 novel peaks (78.8% of its calls)
  • aerts-pd-sn midbrain substantia nigra: unique dopaminergic peaks
  • Veiga adolescent: unique developmental peaks

For an atlas supporting AAV enhancer discovery across diverse regions and life stages, dropping single-cohort peaks removes real biology; downstream cell-type specificity scoring already filters noise.

7. Infrastructure

  • Compute: AWS EC2 r5n.8xlarge spot-persistent (32 vCPU, 256 GB RAM), us-east-1a
  • Storage: 1 TB EBS gp3 with DeleteOnTermination=false (survives spot replacement)
  • Archive: S3 Standard for peak BEDs (small, hot); S3 Deep Archive for raw per-cohort data (large, cold)
  • Spot resilience: cron @reboot fires resume_overnight.sh (curl -C - for partial download resumption), spot_watcher.sh (polls 169.254.169.254 for interrupt notification), auto_uploader.sh (moves stable files to S3 to control disk pressure)

8. Known limitations

  1. Mixed-provenance peaks: CATLAS backbone + some cohort peaks share lineage with CATLAS, creating correlated inclusion. Not independent evidence.
  2. "Super-peaks" (>10 kb): 25% of v2.2 peaks are >10 kb from cohorts with aggressive peak-merge settings. Flagged by peak_width column.
  3. Matrix-mode cohorts: quantification is bounded by the authors' peak axis; cannot recover accessibility in regions authors didn't call peaks.
  4. Spot interrupts: incurred 3× during build (~7 hr compute lost once for an informational test); all recovered automatically via EBS persistence + @reboot cron.
  5. Deep Archive restore latency: required ~5–12 hr for the one-time restore of previously-archived per-cohort peak BEDs. Fixed going forward by keeping peak BEDs in S3 Standard.

9. Version architecture: adding a new cohort

v2.2 is the first LOCKED, STABLE reference union. Each peak receives a stable peak_id_v22 (e.g., nb_v22_0001234) that persists across downstream analyses.

Forward workflow for new cohorts (no Deep Archive restore required):

  1. Download cohort raw data from GEO (direct)
  2. Extract author peak BED (standard pipeline)
  3. Compute cohort's novel peaks vs current union (50% reciprocal overlap rule)
  4. For LOCKED v2.2 analyses: quantify cohort cells against v2.2 union only (new cohort inherits existing peak IDs)
  5. For NEXT version (v2.3): add novel peaks to extension layer, assign new peak IDs starting at nb_v23_*
  6. Store cohort as independent silo at s3://jpm-atacseq-archive-2026/cohorts/<slug>/v2.2.h5ad

Deep Archive restore is only required for retrospective full rebuilds. All v2.2+ peak BEDs live in S3 Standard.
